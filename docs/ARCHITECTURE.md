# Архітектура гри CampLife

**Статус:** чинна з 22.10.2026, чат Гри. Рішення з обґрунтуванням — `docs/DECISION_LOG.md`.
План робіт за спринтами — `docs/ROADMAP.md`.

Головна думка всієї архітектури: **гра — це детермінована симуляція над перевіреним
контентом, а картинка — лише її відображення.** Усе, що може зламати проходження (тупик,
подвійна нагорода, битий сейв), живе в ядрі й контенті, де його ловлять машини. Усе, що
стосується смаку (графіка, звук, тексти), живе зверху, де його оцінюють люди.

---

## 1. Стек

| шар | вибір | чому саме це |
|---|---|---|
| мова | **TypeScript, `strict`** | контракти даних між ядром, контентом і UI мусять ламати збірку, а не гру |
| збірка | **Vite** | статичний бандл, швидкий dev-сервер, без сервера в рантаймі |
| рендер світу | **Phaser 4** (актуальна 4.2.x) | 2D, тайлові мапи Tiled, камера, колізії; Phaser 3 більше не розвивається (останній 3.90, травень 2025). Сумісність перевіряє спайк GAME у спринті 1 |
| інтерфейс | **Preact поверх канви (DOM)** | діалоги, журнал, інвентар — це текст. DOM дає кирилицю, масштаб шрифту, екранний читач і перенос рядків безкоштовно; у канві все це довелося б писати руками |
| мапи | **Tiled** (`.tmj`) | безкоштовний редактор, Phaser читає формат нативно, мапу можна перевірити скриптом |
| тести | **Vitest** + **fast-check** + **Playwright** | юніт, властивості (property-based), наскрізний прохід у справжньому Chromium |
| CI | **GitHub Actions** | репозиторій публічний — хвилини безлімітні |
| хостинг | **GitHub Pages** | статика, безкоштовно, без сервера, без прод-БД |

Чого в стеку **немає** навмисно: сервера, бази даних, акаунтів, аналітики, генеративного ШІ
в рантаймі. Кожне з них — окреме рішення з правовою ціною (`DECISION_LOG.md`, TD-009, TD-010).

## 2. Шари і напрямок залежностей

```
 content/*.json, maps/*.tmj          ← пишуть люди й ШІ-чернетки, стереже валідатор
          │  (збірка падає, якщо валідатор червоний)
          ▼
 src/core/      чисте TS: стан, команди, системи, час, RNG, квести, події, сейви
          ▲  команди            │ знімки стану (read-only)
          │                     ▼
 src/view/      Phaser: сцени, спрайти, камера, рух       src/ui/   Preact: діалоги, меню, журнал
          ▲                                                    ▲
          └──────────── src/platform/: сховище, аудіо, годинник, ввід ──┘
```

🔴 **Правило залежностей перевіряється машиною, а не домовленістю:** `src/core/` не імпортує
нічого з `view/`, `ui/`, `platform/`, `phaser`, `preact`, і не звертається до `window`,
`document`, `Date`, `Math.random`, `localStorage`. Сторож — правило лінтера плюс самотест, який
доводить, що порушення червоніє (закон 1).

Наслідок, заради якого це все: ядро запускається в Node без браузера. Тому тисячі проходжень
гри бот проганяє в CI за секунди, а не людина за тиждень.

## 3. Ядро (`src/core/`)

### 3.1 Стан

Один об'єкт `GameState`, серіалізований у JSON без втрат. **Визначення** (контент) і **стан
проходження** розділені: стан зберігає лише id і змінні, ніколи не копію визначення.

```
GameState {
  version, seed, rngState,
  clock { day, minute },              // ігровий час, не реальний
  player { profileId, transportId, petId?, household, needs, money, locationId, spawnId },
  inventory { itemId → qty },
  quests { questId → { stage, objectives{}, outcome } },
  flags { flagId → bool|int },        // факти світу: «зустрів рейнджера», «намет порваний»
  npcMemory { npcId → { met, trust, remembered[] } },
  grants  Set<grantId>,               // видані нагороди — основа ідемпотентності
  applied Set<commandId>,             // виконані критичні команди
  journal [ … ],
}
```

Позиція персонажа в пікселях у сейв **не потрапляє**: зберігається локація й точка появи. Так
сейв не ламається, коли художник пересуне дерево на мапі.

### 3.2 Команди — єдиний спосіб змінити стан

UI і сцена **не змінюють стан**. Вони надсилають команду:

```
dispatch({ type: 'PurchaseItem', commandId, itemId, qty })
  → { ok: true, state', events[] } | { ok: false, reason: 'NOT_ENOUGH_MONEY' }
```

* передумови перевіряються **до** зміни; зміна застосовується **атомарно** або не
  застосовується зовсім;
* відмова має **код причини** з реєстру — UI показує людський текст за ключем локалізації;
* 🔴 **ідемпотентність:** критична команда несе `commandId`; повтор того самого `commandId`
  повертає попередній результат і нічого не змінює. Нагорода видається за `grantId` рівно раз,
  навіть якщо квест пройдено двічі через цикл (закриває прогалину з `CONTENT-VALIDATOR.md`);
* кожна прийнята команда пишеться в журнал команд. **Сейв + журнал команд = відтворюваний
  баг-репорт**: гравець надсилає файл, ми програємо його й бачимо рівно те саме.

### 3.3 Час і випадковість

* Фіксований крок симуляції; рендер інтерполює. Пауза в меню зупиняє ігровий час.
* Ігровий час іде **діями** (дорога, сон, готування) і повільно — у вільному русі. Немає
  покарання за реальний час поза грою (заборона з `CLAUDE.md`).
* Одна seeded RNG (`sfc32`) у стані. Стан RNG зберігається в сейві, тож завантаження не
  «перекидає кубик» заново.

### 3.4 Системи (кожна — чиста функція `(state, ctx) → state`)

| система | що робить | рівень |
|---|---|---|
| `quest` | етапи, цілі, переходи, нагороди за графом із `quests.json` | зріз |
| `dialogue` | граф реплік з умовами й ефектами | зріз |
| `inventory`, `shop` | предмети, ціни, купівля | зріз |
| `travel` | маршрут між вузлами світу, витрати часу/грошей/сил залежно від транспорту | зріз (1 транспорт) → MVP (3) |
| `needs` | вода, їжа, сон, тепло, настрій — **м'які** модифікатори, не смерть | MVP |
| `events` | відбір події за умовами, вагою й відкатом; розв'язання вибором | MVP |
| `weather` | детермінована погода дня (спершу вигадана, потім за кліматичними нормами) | MVP |
| `npcMemory` | що NPC пам'ятає про гравця і як це змінює діалог | MVP |
| `pet` | потреби й поведінка тварини, вплив на маршрут і кемпінги | MVP |
| `journal` | автоматичний запис подорожі | зріз |

### 3.5 Умови — типізовані, не рядки

Усі умови в контенті — об'єкти, а не текстові вирази:

```json
{ "all": [ { "transport": "camper" }, { "pet": "dog" }, { "flag": "met.ranger" } ] }
```

Причина одна: **валідатор може їх прочитати.** Рядковий вираз на кшталт `"camper && dog"`
валідатор не розбере, і гілка «тільки для кемпера з собакою» стане сліпою зоною. З об'єктами
валідатор проганяє досяжність окремо для кожного варіанта гравця (див. §6.2).

## 4. Контент

| що | де | формат |
|---|---|---|
| квести, предмети, NPC, локації, події, факти | `content/*.json` | діючий формат валідатора, `docs/CONTENT-VALIDATOR.md` |
| діалоги | `content/dialogue/*.json` | граф вузлів: репліка → вибори → умова → ефект → наступний вузол |
| профілі, транспорти, тварини | `content/variants.json` | осі варіантів гравця |
| тексти | `content/locales/uk.json`, `en.json` | ключ → рядок, жодного тексту в коді |
| мапи | `maps/*.tmj` | Tiled, шари `ground`, `objects`, `collision`, `spawns`, `triggers` |
| реальні факти | `content/facts.json` | джерело, дата перевірки, тип; реєстр із `04-bazy-znan.md` |

**Мови:** українська й англійська з першого дня. Псевдолокаль (`[!! Ŭķŕāïńşŝ ++ !!]`) для
перевірки, що інтерфейс не обрізає довші рядки.

**ШІ як інструмент автора, не рантайму:** чернетки діалогів генеруються через `fal-ai/any-llm`
у GitHub Action (ключ лише в секретах), лягають у PR як звичайний JSON, проходять валідатор і
людську редактуру. Гра не робить жодного мережевого запиту під час проходження.

Чому не Ink чи Yarn Spinner: вони зручні для письменника, але їхні умови — рядки у власній мові,
і валідатор не зможе довести, що гілка досяжна для кожного варіанта гравця. Для гри, де головний
ризик — тупик у комбінаториці, це вирішальне (TD-005).

## 5. Збереження

* Сховище — **IndexedDB**, резерв — `localStorage`; експорт/імпорт файлом `.camplife`.
* Формат: `{ format: 'camplife-save', version, checksum, state, commandLog }`.
* **Атомарність:** запис у тимчасовий слот → перевірка контрольної суми → перемикання вказівника.
  Обрив вкладки посеред запису лишає попередній сейв цілим.
* **Міграції:** ланцюг `v1→v2→…` чистими функціями. Кожна випущена версія сейву лишається в
  `tests/saves/` **назавжди** як фікстура, і CI доводить, що вона завантажується в поточній
  версії. Це урок Stardew/Dinkum із GDD: біті сейви після оновлення — найдорожчий клас дефектів.
* Сейв не містить нічого, що ідентифікує людину. Серверних сейвів і акаунтів у першій версії
  немає (TD-009).

## 6. Якість: сторожі, і кожен уміє почервоніти

Закон 1 — головний для цієї гри. Кожен сторож нижче має самотест на навмисно зламаному прикладі.

### 6.1 Перелік

| сторож | ловить | де |
|---|---|---|
| валідатор контенту | тупики графа, биті посилання, подвійні нагороди, відсутні переклади | діє, 51/51 самотест, 24/24 мутації |
| валідатор діалогів | недосяжні вузли, діалог без виходу, умова на неіснуючий прапорець | спринт 3 |
| **варіантний валідатор** | досяжність кінця кампанії для **кожної** комбінації профіль × транспорт × тварина | спринт 5 |
| валідатор мап | точка появи замурована, тригер квесту недосяжний пішки, тайл поза набором | спринт 2 |
| сторож меж ядра | `core/` торкнувся DOM, Phaser, `Date`, `Math.random` | спринт 1 |
| інваріанти властивостей | гроші ≥ 0, нагорода ≤ 1 раз, сейв→завантаження = той самий стан | спринт 1–3 |
| реплей-тести | журнал команд дає той самий хеш стану на кожній збірці | спринт 3 |
| **бот-гравець** | тисячі випадкових і жадібних проходжень ядра без рендеру; шукає стан, з якого кампанію не завершити | спринт 4 |
| сейв-фікстури | старий сейв не відкривається новою версією | спринт 3, далі завжди |
| сторож палітри | спрайт поза палітрою основного набору (вбивця гармонії) | спринт 2 |
| наскрізний прохід | Playwright проходить зріз у збірці від старту до журналу | спринт 3 |
| бюджети | розмір бандла, час старту, кадри на секунду на еталонній сцені | спринт 4 |

### 6.2 Чому варіантний валідатор — серце якості

48 сімей подій × 12 профілів × 3 транспорти × тварини — це тисячі станів. Людина перевірить
десяток. Тому:

1. валідатор графа проганяється **для кожної** комбінації осей окремо — це дешево, граф малий;
2. бот проходить **попарне покриття** осей (кожна пара значень хоча б раз) плюс випадкову
   вибірку з фіксованим зерном;
3. знайдений тупик стає фікстурою в самотесті назавжди.

### 6.3 Що машина не перевірить

Чи цікаво. Чи смішно. Чи гарно. Це плейтест із живими людьми, які не брали участі в розробці, —
окремі картки в спринтах 4 і 9, і без них реліз не вважається готовим.

## 7. Арт і звук

* Основа — **LPC, 32×32** (OD-013, 22.10.2026; Kenney 16×16 — лише сірий прототип S01–S02). Масштаб рендеру — ціле число (×3 або ×4),
  `pixelArt: true`, без згладжування.
* Новий об'єкт доводиться до палітри, масштабу й напрямку світла набору — **сторож палітри**
  це перевіряє автоматично.
* Прогалина — **кемпер/караван.** Варіанти: генерація FAL + конвеєр + ручна правка під
  палітру або людина-піксель-артист. Вибір — питання смаку й грошей власника (спринт 2).
* Шрифт — піксельний із **повною українською кирилицею** (і, ї, є, ґ, апостроф) під ліцензією
  OFL; перевіряється автоматично рендером тестового рядка всіх літер.
* Звук — CC0-набори; кожен файл — рядок у `docs/LICENSE_REGISTER.md`.

## 8. Реальна Європа

* **Прототип і зріз — вигаданий регіон.** Реальна географія — з MVP, коридор Бельгія–Нідерланди
  (рішення з `01-verdikt.md`).
* Дані кемпінгів — **експорт зрізу** від чату Сайту через `bridge/inbox/`, файлом у репозиторії
  гри. Прямого доступу до БД сайту немає й не буде.
* Дорожній граф — OpenStreetMap, ODbL: атрибуція в грі й у титрах. Умови на дані й на тайли —
  різні; тайлів OSM гра не використовує, лише спрощений граф.
* 🔴 Реальні кемпінги можуть бути в грі, **реальні люди — ні.** Вигаданий NPC біля справжнього
  кемпінгу не говорить від імені власника. Персонажі NPC прив'язуються до вигаданих місць або
  до загальнодоступних (місто, траса), не до приватного бізнесу.
* Кожен реальний факт (правила вогнищ, ціни, заборони) — запис у `facts.json` з джерелом і
  датою. Ігрове спрощення позначається як спрощення.

## 9. Доставка

* Кожен PR: лінт, типи, юніт і властивості, валідатор (самотест, мутації, контент), валідатор
  мап, збірка, Playwright-прохід. Усе блокує злиття.
* `main` → GitHub Pages автоматично. Версія гри й хеш коміту видно в меню — щоб баг-репорт
  називав збірку.
* Рецензент на кожен PR із кодом — окремий агент або людина, не автор (рішення власника).

## 10. Відкриті питання, які архітектура свідомо не закриває

| питання | чому відкрите | хто вирішує |
|---|---|---|
| акаунти й серверні сейви | GDPR, вік гравців, модель користувача сайту; у вердикті були в MVP | власник + чат Сайту, через `bridge/` |
| домен гри (`game.camptribe.eu`?) | DNS — зона Сайту | власник + чат Сайту |
| кемпер: хто малює | гроші й смак | власник |
| музика | гроші й смак | власник |
| точний текст Core Rules, контрактів, ST-001…ST-015 | джерело лежить локально | запит чату Сайту, `bridge/inbox/` |
