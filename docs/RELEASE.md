# Реліз-цикл: версія, список змін, ланцюжок до гравців

Рішення власника 24.10.2026 (OD-014, `docs/DECISION_LOG.md`): на власному сайті — часті малі релізи, у YouTube
Playables — зібрані й рідше, бо кожне оновлення там проходить сертифікацію заново. Картка: GAME-102.

## Що вже стоїть і що стереже

| що | де | хто стереже |
|---|---|---|
| номер версії (semver) | `version` у `package.json` (і в `package-lock.json`) | `scripts/release/check-release.mjs` |
| список змін людською мовою | `CHANGELOG.md`, найновіший запис угорі | той самий сторож |
| версія видна в грі | меню паузи: `<Назва> v<версія> · <повний SHA>` (`src/core/build-info.ts`, `[data-ui="build"]`) | `src/core/build-info.test.ts`, `tests/e2e/game-119.spec.ts` |

Сторож входить у `npm run validate` (тож у `npm run check` і в CI) і червоніє, якщо: версія не semver; верхній запис
журналу не semver, без дати чи не найновіший; `package.json` ≠ верхній запис; `package-lock.json` відстав.
Самотест і мутація (`--self-test`, `--mutate`) доводять, що кожна перевірка вміє почервоніти.

## Як зрізати версію

1. Окремий PR, лише про реліз. Нових фіч у ньому немає.
2. У `CHANGELOG.md` вгорі додати запис `## [X.Y.Z] — РРРР-ММ-ДД` з розділами «Додано», «Змінено», «Виправлено».
   Пишемо те, що помітить гравець або власник, а не імена файлів. Нічого з сирого GDD, жодних секретів: репозиторій публічний.
3. Те саме `X.Y.Z` — у `package.json` і `package-lock.json` (`npm version X.Y.Z --no-git-tag-version`).
4. `npm run check` зелений. Розбіжність версії й журналу червоніє сама.
5. Рецензент, злиття в `main`. Тег `vX.Y.Z` ставить власник, коли публікує (див. нижче).

Правило номера: до першого публічного релізу — `0.x.y`; нова можливість для гравця — `x`, виправлення — `y`;
`1.0.0` — повна гра за рішенням власника.

## Ланцюжок

```
main (CI зелений) → preview (закритий, пароль) → власник дивиться й погоджує → гравці
```

1. **Preview.** Кожне злиття в `main` саме збирає закритий перегляд (`.github/workflows/preview.yml`,
   Cloudflare Pages, гілка `preview`, вхід за логіном і паролем). Кнопок тиснути не треба. Зелений прогін
   workflow `preview` на повному SHA — доказ, що саме ця збірка там лежить; версія й SHA видно в меню паузи.
2. **Власник.** Відкриває preview, перевіряє, пише погодження в картці Jira релізу: версія, посилання на прогін
   `preview`, слово «погоджено». Без цього запису реліз не робимо (погодження власника — не наша дія).
3. **Свій сайт (часто).** Після погодження власник вмикає публікацію: публічного сайту поки немає (рішення 23.10.2026),
   workflow `pages` запускається лише вручну (Actions → pages → Run workflow). Порядок і кнопку підтверджує власник.
4. **YouTube Playables (рідко).** Збираємо кілька версій з сайту в один пакет; подаємо лише після першого
   повного сценарію (10+ хв) і з вимогами YouTube (без зовнішніх запитів, збереження й реклама через свої модулі).
   У журналі змін пакета перелічено всі версії, що в нього ввійшли.

## Чого тут ще немає (чекає власника)

* Перший реліз за цим циклом: погодження власника й посилання на прогін preview.
* Публічний сайт і подача в YouTube: потребують окремого рішення власника.
