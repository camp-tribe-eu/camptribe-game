# Валідатор контенту

Сторож усього ігрового контенту. Специфікація: `brain/Передача/05-pershyi-kod.md`.
Код: `scripts/validate-content.mjs` і `scripts/validator/`. Без залежностей, лише Node.

```
node scripts/validate-content.mjs               # перевірити content/
node scripts/validate-content.mjs --self-test   # довести, що кожна перевірка червоніє
node scripts/mutate-validator.mjs               # довести, що самотест помічає вимкнену перевірку
```

## Формат `content/`

| файл | що | id |
|---|---|---|
| `meta.json` | `{ start, locales: [...] }` | — |
| `profiles.json` | життєві профілі гравця; `transports` — які транспорти доступні профілю | `profile.назва` |
| `transports.json` | транспорт | `transport.назва` |
| `animals.json` | тварини (`animal.none` зарезервовано за «без тварини»); `transports` — чим тварину можна везти | `animal.назва` |
| `quests.json` | етапи кампанії: `optional`, `end`, `requires`, `objectives`, `transitions`, `reward` | `ST-001` або `q.назва` |
| `items.json` | предмети | `item.назва` |
| `npcs.json` | NPC: `locationId`, `unlockedBy`, `sells` | `npc.назва` |
| `locations.json` | локації: `unlockedBy`, `items` | `loc.назва` |
| `roads.json` | дороги між локаціями: `from`, `to`, `twoWay`, `ways[]` (транспорт, хвилини, центи); перевірка `roads`: кожна локація досяжна від дому й назад для кожного транспорту (`ROAD_UNREACHABLE`, `ROAD_NO_RETURN`), одне ребро на пару в кожен бік (`ROAD_DUPLICATE`) | `road.назва` |
| `events.json` | події: `repeatable`, `reward` | `ev.назва` |
| `facts.json` | зовнішні факти: `source`, `checkedAt` (РРРР-ММ-ДД), `kind` | `fact.назва` |
| `locales/<мова>.json` | ключ → переклад | — |
| `dialogue/<назва>.json` | один діалог-граф на файл (розділ «Діалоги») | `dlg.назва` |

Нагорода — `{ grantId: "rw.назва", items, money, once }`. `grantId` унікальний на весь контент.

Схеми строгі: невідоме поле — помилка. Так у **визначення** не потрапляє **стан проходження**
(`completed`, `progress`, `visited`…), і одруківка в назві поля не проходить мовчки.

## Діалоги (GAME-28)

Діалог — власний JSON-граф (TD-005), по файлу на діалог у `content/dialogue/`. Завантажувач
складає їх у `content.dialogues`; не-JSON у теці — `CONTENT_UNKNOWN_FILE`, зламаний JSON —
`CONTENT_PARSE`. Справжній зразок — `content/dialogue/elise-greeting.json`.

```
Dialogue  = { id: "dlg.<назва>", npcId: "npc.…", start: "<вузол>", nodes: Node[≥1] }
Node      = { id: "<a-z0-9->", speaker: "npc"|"player", textKey,
              рівно одне з: end: true | next: "<вузол>" | choices: Choice[≥1] }
Choice    = { textKey, next: "<вузол>", when?: Cond, effects?: Effect[] }
Cond      = { flag: "f.…" } | { notFlag: "f.…" } | { quest: "<id квесту>", status: "active"|"completed" }
          | { transport: "transport.…" } | { remembers: "m.…" } | { notRemembers: "m.…" }
          | { all: Cond[≥1] } | { any: Cond[≥1] }
Effect    = { setFlag: "f.…" } | { startQuest: "<id квесту>" } | { completeObjective: { quest, objective } }
          | { remember: "m.…" }
```

Умова й ефект — типізовані об'єкти (TD-006) рівно з одним ключем-дискримінатором; рядок
`"car && x"`, два ключі разом чи невідомий ключ — `SCHEMA_INVALID`. Семантика для рушія: `when`
приховує вибір, якщо умова хибна; `effects` виконуються по черзі під час вибору; `end` закриває
розмову; `next` — продовження без вибору гравця.

Перевірки:
* `dialogue-refs` → `DIALOGUE_REF_MISSING`: `npcId`, `start`, усі `next`, квест і транспорт в умовах
  (зокрема вкладених), квест в `startQuest`, квест і ціль у `completeObjective`.
* `dialogue-reachable` → `DIALOGUE_NODE_UNREACHABLE`: обхід від `start` за `next` і **всіма** виборами
  (умовними теж). Якщо `start` не існує — мовчить, першопричину вже назвав `DIALOGUE_REF_MISSING`.
* `dialogue-dead-end` → `DIALOGUE_DEAD_END`: з кожного вузла має бути шлях до `end` лише
  **безумовними** виходами (`next` або вибір без `when`). Ловить вузол без виходу, вузол лише з
  умовними виборами і петлю без `end`. **Ціна хибного спрацювання (закон 5):** взаємовиключні
  умови, що разом покривають усе (`flag` / `notFlag`), валідатор не доводить — автор додає
  безумовний вибір. Це дешевше, ніж гравець, що застряг у розмові.
* `dialogue-flags` → `DIALOGUE_FLAG_NEVER_SET`: кожен `flag`/`notFlag` (зокрема всередині `all`/`any`)
  мусить ставитись хоча б одним `setFlag` у будь-якому діалозі. Квести прапорців поки не
  ставлять (у схемі квестів немає ефектів) — з'являться, додати їх у множину.
* `dialogue-memory` → `MEMORY_NEVER_SET` (GAME-48): кожен `remembers`/`notRemembers` читає пам'ять NPC,
  чия це розмова, і мусить мати здійсненний `remember` у розмові з **тим самим** NPC. Нерухома точка
  спільна з прапорцями (`settable`): сетер за умовою, що сама вимагає свій факт, — не сетер. Пам'ять
  змінює лише ефект `remember` (ядро: `npcMemory` у стані, сейв v2); подія в дорозі NPC не має, тож
  `remember` у ній — `EVENT_EFFECT_UNSUPPORTED`. `remembers` і `notRemembers` того самого факту в одному
  `all` — `DIALOGUE_COND_CONTRADICTION`.
* Наявні перевірки розширено: `id-format` (`dlg.…`, id вузла, прапорець `f.…`, факт `m.…` — без `_`),
  `id-unique` (id діалогу, id вузла в діалозі), `locale-keys` (`textKey` вузлів і виборів →
  `LOCALE_MISSING`).

## Комбінації: профіль × транспорт × тварина

Квест, ціль, перехід, NPC і локація можуть мати умову на стан гравця:

```json
"when": { "profiles": ["profile.…"], "transports": ["transport.…"], "animals": ["animal.…", "animal.none"] }
```

Усі названі виміри мусять збігтися; всередині виміру — будь-яке значення зі списку. Порожній
список — `SCHEMA_INVALID`. Вимір без жодного запису в контенті не перебирається. Тварина —
щонайбільше одна: `animal.none` або одна з `animals.json` (припущення каркаса, звірити з
реальним переліком профілів).

**Сумісність.** Профіль і тварина можуть мати `"transports": ["transport.…"]` — лише ці
транспорти їм доступні; немає поля — доступні всі. Несумісна комбінація (собака на велосипеді,
профіль без авто за кермом авто) **не перебирається**: гравець її не обере, тож тупик у ній —
хибне спрацювання, яке змушувало б писати контент для неіснуючого гравця. Без тварини можна
завжди. Зворотний бік: транспорт, яким не може їхати жоден профіль, — `COMBO_OPTION_UNUSABLE`
(профіль і тварину окремо не перевіряємо: на чистому контенті профіль завжди має комбінацію, а
тварина недоступна рівно тоді, коли недоступні всі її транспорти). Умова `when`, якій не
відповідає жодна дозволена комбінація, — `WHEN_UNSATISFIABLE`: інакше ціль чи перехід мовчки
зникають з усіх комбінацій. Перехід перевіряється разом з умовами квесту-джерела й квесту-цілі,
навіть без власного `when`; квест із мертвою власною умовою звітує один раз, без дублів з його
переходів і цілей. Ціна: власний дефект такого переходу чи цілі стане видно лише після
виправлення умови квесту. Обидві перевірки біжать лише на чистому контенті, як і `combos`.

Перевірка `combos` будує вигляд контенту для **кожної** комбінації: квести, цілі й переходи з
чужою умовою зникають, NPC і локації з чужою умовою стають недоступними (ціль на них червоніє,
а не зникає мовчки). Квести, недосяжні в цій комбінації, відсікаються — гравець їх не побачить.
На решті проганяються `objective-completable`, `cycle-exit`, `main-gate`, `path-to-end`,
`optional-decline`, `branch-next`; знахідка звітує один раз із числом комбінацій і прикладом.

`combos` запускається лише на контенті, чистому в цілому: на зламаних посиланнях вона дублює й
затуляє першопричину. Ціна: дефект комбінації видно після виправлення загального.

## Що означає «гарантовано»

Ціль вважається досяжною, лише якщо все потрібне для неї гарантоване **на кожному** шляху до
цього етапу. Квест X гарантований перед етапом q, якщо без переходів `complete` з X етап q
недосяжний. Відмова (`decline`) — не завершення, тож нагорода необов'язкового квесту ніколи не
рахується гарантованою. Нагороди подій теж не рахуються: подія може не статися.

## Давність фактів (GAME-56)

`content/facts.json` — реєстр реальних фактів (правила кемпінгу, вогню, природних територій), на
які може спиратися гра. Кожен факт: `source` — офіційна сторінка (уряд, агентство природи,
офіційний туризм), `checkedAt` — день, коли твердження справді звірено зі сторінкою, `kind`.
Без джерела чи з кривою датою — **помилка** (`fact-source`).

Факт, звірений понад **365 днів** тому, — `FACT_STALE`, **попередження**: CI друкує
`::warning::`, `PASS` лишається, код виходу 0. Попередження не вимикає й пізні перевірки
комбінацій (вони біжать на контенті без **помилок**).

**Чому 365.** Правила, що нас цікавлять, живуть у річному ритмі: заборони вогню й коди
пожежної небезпеки оголошують посезонно, бівак-зони й правила територій переглядають між
сезонами, і один повний сезон — найдовший строк, за який твердження ще можна вважати звіреним.
Коротший поріг (90–180 днів) жовтів би майже весь реєстр щокварталу без зміни на сторінках —
шум, до якого звикають і перестають читати. **Чому попередження, а не помилка** (закон 5, ціна
хибного спрацювання): факт старіє з календарем, а не з комітом; помилка заблокувала б
непов'язаний PR того дня, коли факту виповнився рік. Ціна пропуску — жовтий рядок у CI, який
видно, але який не зупиняє роботу.

«Сьогодні» — параметр `validate(content, { today })`: CLI бере справжню дату, самотест —
`TODAY = '2026-10-22'` з `scripts/validator/fixtures.mjs`. Межа перевірена з обох боків
(365 днів — тихо, 366 — `FACT_STALE`), а самотест ще й звіряє код виходу через
`scripts/validator/verdict.mjs` — той самий модуль, що в CLI: попередження → 0, помилка → 1.

## Самотест

Приклад може мати `count: { code, n }` — точну кількість знахідок цього коду. Множина кодів
дублів не бачить, `count` бачить; сама звірка кількості має власний самотест (більше, менше,
рівно).

Еталон — синтетичний міні-сюжет у `scripts/validator/fixtures.mjs`, **не контент гри**. Кожен
зламаний приклад — еталон плюс одна поломка, і для нього заданий **точний** набір кодів: менше —
перевірка сліпа, більше — вона стріляє по сусідах. Позитивні контролі (очікують порожній набір)
доводять, що коректне не червоніє.

Самотест також падає, якщо якийсь код із реєстру не має прикладу, на якому він спрацював, або
якщо кількість виконаних кроків не збігається з базою.

**Знайшов дефект контенту в грі — додай приклад у `FIXTURES`.** Інакше він повернеться.

## Перший контент (GAME-35)

`content/` — перший зріз Прологу «Одна вільна ніч»: ST-001…ST-005 і необов'язковий
`q.elise-bike-area` лише для велосипеда; 2 профілі × 2 транспорти × (без тварини | кішка) → 5
дозволених комбінацій. Прапорець `--allow-missing-content` із `npm run validate` прибрано: теки
немає — `CONTENT_MISSING`, код 1.

Розбіжність: у `docs/CONTENT_REGISTRY.md` id профілів записані з `_` (`profile.family_teen`), а
`ID_FORMAT` дозволяє лише `[a-z0-9]` з `.`/`-`. У контенті — `profile.family-teen`,
`profile.solo-explorer`; реєстр треба вирівняти. Схема подій не має `tags`, тож правило
«Пролог без `negative`» поки тримається рецензією, а не валідатором.

## Чого валідатор поки НЕ перевіряє

Чесний перелік, щоб зелене не читалось ширше, ніж воно є:

* **Реальні профілі.** Схема й перебір комбінацій є, але доведені лише на ДВОХ СИНТЕТИЧНИХ
  профілях самотесту. Перелік 12 профілів — у `docs/CONTENT_REGISTRY.md` (GAME-51, з GDD власника);
  поки `content/profiles.json` немає, вимір профілю не перебирається.
* **Домогосподарство** і **кілька тварин одночасно** не моделюються.
* **Вкладені умови поза ланцюгом квест → ціль/перехід → квест.** `when` NPC-видавця
  (`giverId`), локації квесту (`locationId`) і необов'язкової цілі не звіряються з `when`
  квесту: якщо вони ніде не перетинаються, валідатор мовчить (рецензія PR #10).
* **Умови на стан світу** (пройдені квести, гроші, погода) — `when` знає лише стан гравця.
* **Умови на стан світу на переходах.** Перехід знає лише стан гравця (`when`); цикл із виходом, умова якого ніколи не
  справджується, пройде як коректний.
* **Діалоги в комбінаціях.** Умова `transport` у діалозі не звіряється з комбінаціями: вибір
  лише для транспорту, яким не їде жоден профіль, валідатор не помітить (але безумовний вихід
  поруч усе одно обов'язковий, тож softlock це не дає). Чи ставиться прапорець **раніше**, ніж
  читається, — не перевіряється: лише те, що його ставить хоч щось.
* **Ідемпотентність команд** (контракт з 05-pershyi-kod.md) — це ядро гри, не контент.
* **Повторне завершення квесту в циклі** видасть його нагороду знову; `reward-once` стереже лише
  дублікати `grantId` і повторювані події.
