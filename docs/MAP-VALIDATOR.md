# Валідатор мап (GAME-23)

Сторож геометричних тупиків: квест досяжний у графі, але не на мапі. Валідатор контенту
(`docs/CONTENT-VALIDATOR.md`) бачить граф квестів; цей — клітинки, стіни й точки появи.
Код: `scripts/maps/`. Без залежностей, лише Node.

```
node scripts/maps/validate-maps.mjs                        # перевірити maps/
node scripts/maps/validate-maps.mjs --allow-missing-maps   # мап немає → NOT RUN (код 0), не PASS
node scripts/maps/validate-maps.mjs --dir <тека>           # перевірити іншу теку
node scripts/maps/validate-maps.mjs --self-test            # довести, що кожна перевірка червоніє
node scripts/maps/mutate.mjs                               # довести, що самотест помічає вимкнену перевірку
```

Коди виходу: `0` — перевірено й чисто (`PASS · …` з числами); `1` — знахідки або самотест упав;
`0` + `::warning::NOT RUN` — мап немає, і це явно дозволено прапорцем.

## Формат мапи

Tiled JSON (`.tmj`) у `maps/` (підтеки теж читаються). Приклад: `maps/camp-prologue.tmj`.

* **Орієнтація** `orthogonal`, `infinite: false`. Дані тайлових шарів — масивом
  (Tile Layer Format = CSV), не base64. Тайлсети **вбудовані** (Embed Tileset), не `.tsx`.
* **gid 0** — порожня клітинка. Старші біти gid (`0x80000000 | 0x40000000 | 0x20000000 | 0x10000000`)
  — прапорці віддзеркалення/повороту, знімаються перед звіркою з тайлсетом.
* **Колізія.** Клітинка непрохідна, якщо (а) в шарі з властивістю `collides = true` у ній
  непорожній тайл, або (б) у будь-якому шарі в ній тайл, що в тайлсеті має властивість
  `collides = true`. Шар без `collides` (декор) не блокує. Групи шарів розгортаються.
* **Об'єкти** — у шарі об'єктів з назвою рівно `objects`. Кожен має `type` (або `class` з Tiled
  1.9) — `spawn` | `trigger` | `npc` — і непорожнє `name`. Позиція в пікселях → тайл:
  `floor(x / tilewidth)`, `floor(y / tileheight)`; для об'єкта з шириною/висотою — його **центр**.
  Тайловий об'єкт (з `gid`) у Tiled має початок у лівому **нижньому** куті — це враховано.
* **Рух** — 4 напрямки. Діагональ між двома стінами — не прохід.
* **Тригер** спрацьовує, коли на нього стають: його клітинка мусить бути досяжна.
  **NPC** говорить із сусідньої клітинки: досить досяжного сусіда (NPC може стояти в ніші).

## Перевірки → коди → доказ у самотесті

Кожен зламаний приклад у `scripts/maps/fixtures.mjs` — еталонна мапа 10×7 плюс одна поломка, і
для нього заданий **точний** набір кодів.

| перевірка | код | що | приклад, що доводить |
|---|---|---|---|
| завантажувач | `MAPS_MISSING` | теки немає, порожня, або в ній жодного `.tmj` (закон 4) | «теки maps/ немає», «тека порожня», «у теці лише README.md» |
| завантажувач | `MAP_PARSE` | `.tmj` не JSON; `.tmx` (XML) не читаємо | «файл .tmj — не JSON», «XML .tmx замість JSON» |
| `structure` | `MAP_STRUCTURE` | не orthogonal, infinite, base64, зовнішній тайлсет, розмір шару ≠ мапі, невідомий тип шару | шість прикладів «структура» |
| `tiles` | `TILE_OUT_OF_TILESET` | gid (без прапорців) не належить жодному тайлсету — і в шарах, і в тайлових об'єктах | «тайл поза тайлсетом», «gid у проміжку між двома тайлсетами», «тайловий об'єкт із gid поза тайлсетом» |
| `objects` | `OBJECT_INVALID` | тип не з трьох, порожнє ім'я, `type` ≠ `class`, дубль імені тригера/NPC | «одруківка в типі (spwan)», «тригер без імені», «type і class суперечать», «два NPC з одним іменем» |
| `bounds` | `OBJECT_OUT_OF_BOUNDS` | об'єкт поза мапою | «NPC і тригер поза мапою» (count = 2) |
| `spawn-present` | `MAP_NO_SPAWN` | жодної точки появи (або шару `objects`) | «мапа без точки появи», «шар objects названо інакше» |
| `spawn-free` | `SPAWN_BLOCKED` | точка появи на колізії або без жодного прохідного сусіда | «замурована точка появи», «точка появи на стіні» |
| `reach` | `TARGET_UNREACHABLE` | тригер чи NPC недосяжний пішки хоча б з однієї точки появи | «тригер за стіною (лише по діагоналі)», «тригер на тайлі стіни», «NPC за стіною», «стіна в групі шарів», «стіна з тайла з collides», «досяжні з однієї з трьох точок появи» (count = 2) |
| виконавець | `INTERNAL_ERROR` | перевірка впала винятком — червоне, не зелене | — |

**Семантика «з кожної точки появи».** Ціль мусить бути досяжна з **кожної** точки появи. Звіт —
**один на ціль**, з числом точок, з яких не дійти, і їхніми іменами
(`недосяжна пішки з 2 із 3 точок появи: s.main, s.alt`). Дублі стереже `count` у прикладі.

**Без дублів між кодами.** Точка появи поза мапою, на стіні чи замурована має свій код і в
пошуку шляху не бере участі; ціль поза мапою — теж. Ціна: якщо на мапі **всі** точки появи
заблоковані, недосяжні цілі стане видно лише після виправлення точки появи. Структурні помилки
(`MAP_STRUCTURE`) зупиняють решту перевірок цієї мапи: на зламаній структурі вони дублюють і
затуляють першопричину.

## Самотест і мутації

Самотест падає, якщо: набір кодів прикладу не збігся точно; `count` не збігся (сама звірка
`count` має доказ в обидва боки); якийсь код реєстру не спрацював у жодному прикладі (сама звірка
покриття має доказ, що вміє почервоніти); число виконаних кроків ≠ базі. Позитивні контролі
(NPC у ніші, gid з прапорцями, тайловий об'єкт, прямокутник із краєм на стіні, `class`, декор без
колізії, другий тайлсет) чекають `[]`.

`mutate.mjs` у тимчасовій копії `scripts/maps/` вимикає кожну з 7 перевірок (маркер
`// @check:<id>` → `return [];`) і робить 23 точкові мутації (діагональний рух, «досить будь-якої
точки появи», звіт на кожну точку, ігнор прапорців gid, ігнор групи шарів, NOT_RUN як OK тощо).
Кожна мусить звалити самотест рядком `SELF-TEST: FAILED`. Вижила — друкується як `ПЕРЕЖИЛА`.

## Чого валідатор поки НЕ перевіряє

* **Зв'язок мапи з контентом** — не тут, а в `src/view/world/map-content.test.ts` (GAME-32): для мап
  гри (`public/maps/`, які вантажить сцена) кожен NPC — з `content/npcs.json`, кожен тригер — взаємодія
  каталогу, кожен NPC локації мапи (`locationId` у властивостях мапи) має місце на ній; і сцена вантажить
  лише мапи з `public/maps/`, яку `npm run validate` перевіряє цим валідатором (`--dir public/maps`).
  Для навчальних мап у `maps/` зв'язок не звіряється.
* **Переходи між мапами** (двері, виходи): кожна мапа перевіряється окремо.
* **Динамічні перешкоди** — NPC, що ходять, двері, що відчиняються квестом, транспорт. Стіни лише
  статичні; NPC сам не блокує прохід.
* **Розмір персонажа.** Персонаж = 1 тайл; прохід шириною в тайл вважається прохідним.
* **Поворот об'єктів** (`rotation`), полігони й еліпси — береться центр обмежувального прямокутника.
* **Наявність файлу зображення тайлсету** і його розмір проти `tilecount` не звіряються.
* **Ізометричні, гексагональні, нескінченні мапи, base64/zlib, зовнішні `.tsx`** — відхиляються
  як `MAP_STRUCTURE`, а не підтримуються.
