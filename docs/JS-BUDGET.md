# JS-бюджет: з чого складається main і що з нього можна прибрати (GAME-330)

Поріг `jsFailBytes` = 2 621 440 Б (`budgets.json`) — сума всіх `dist/assets/*.js`. Поріг і сторож НЕ чіпались.

## Вимір

Збірка з sourcemap у тимчасову теку (`npx vite build --sourcemap --outDir <tmp>`), байти кожного сегмента main
віднесені до його джерела за картою. Сума за картою 1 252 471 Б = розмір файлу (збіг). Phaser (1 367 759 Б) — сторонній рушій, не чіпаємо.

Стан ДО змін: main 1 252 471 Б + phaser 1 367 759 Б + spike 1 153 Б = 2 621 383 Б, запас 57 Б.
(У картці GAME-330 стояло main 1 087 108 Б — це число не збігається з реальною збіркою c6dfcae.)

## Що прибрано (`vite.config.ts`, лише збірка; файли в репозиторії, тести, валідатор і e2e лишились повними)

1. `assets/credits.json`: поле `authors` (59 КБ, групування за автором — Shell його не читає; він групує `files` сам),
   а також `generated_by`, `source`, `drm_ok`. Новий плагін `strip-credits-docs`.
2. `content/flags.json`: чорний список (`owner`, `note`) замінено білим (`id`, `type`, `values`, `journal`) — додатково
   пішли `initial`, `kind`, `aka`, `reserved`, `generatedFrom`, `valuesFrom` (читають лише валідатор і тести, перевірено grep).

Результат: JS 2 621 383 → 2 558 997 Б (−62 386 Б; main 1 252 471 → 1 190 085). Запас під порогом 57 → 62 443 Б.

Перевірено: `tsc -p tsconfig.node.json`, `eslint vite.config.ts`, `vitest src/content/flags.test.ts` (4 PASS), `npm run build && npm run budget` (OK).
NOT RUN: повні vitest, `npm run validate`, e2e (включно з `tests/e2e/credits.spec.ts`, який читає `assets/credits.json`
напряму і порівнює з DOM; у збірці Shell бере лише `files` і `licences`, тож DOM не змінюється — але це висновок із коду, не запуск).

## Чого не знайдено (перевірено, прибирати нема чого)

- Тестові перемикачі (`testSwitches`, `__game.storyPing/rewardTitle/rewardSum`) закриті `import.meta.env.MODE === 'e2e'`, що в продакшені
  вирізається; `test-switches.ts` важить 1,7 КБ. `window.__game.probe/read/…` вантажиться завжди, але це лічені КБ і вона
  переплетена зі сценою (`probe` читає й сам код гри) — ризик більший за виграш.
- `bot.ts` потрапляє в збірку через `viability.ts` (сейв-перевірка досяжності кінця), але дерево скорочує його до 0,6 КБ.
- Дублікатів JSON-даних у двох копіях немає: кожен JSON імпортований один раз (діалоги — через `import.meta.glob`, eager).

## Що ще можна зекономити, і за яку ціну

| Варіант | Виграш у JS | Ціна / ризик |
|---|---:|---|
| Титри: групувати файли за (автори, ліцензія, джерела) під час збірки — 101 запис → 39 груп; Shell і `Credits` перейдуть на `groups` | ≈ 37 КБ | зміна типу `Credits`, `Shell.tsx`, e2e `credits.spec.ts`; у dev/тестах форма даних інша, ніж у збірці — треба спільний нормалізатор |
| `assetsInlineLimit: 0` — PNG < 4 КБ лишаються окремими файлами | ≈ 85 КБ у JS (+ ≈ 64 КБ файлів) | ≈ 60 додаткових запитів на старті; гра ходить «першим кадром < 1,5 с» (OD-014..016) — міряти `game-38`; по суті перенесення байтів із бюджету в інший, а не їх зникнення; нова вимога «без зовнішніх запитів» для YouTube не порушується (те саме джерело) |
| Ліниве завантаження локалі неактивної мови (uk/en по ≈ 170/121 + 57/41 КБ) динамічним `import()` | ≈ 160–225 КБ | гра працює офлайн: друга мова мусить лежати в пакеті як окремий чанк; зміна мови стає асинхронною; перший кадр — лише з активною мовою; сума `dist/assets/*.js` НЕ зменшиться (чанк теж `.js`) — це виграш у стартовому, а не в бюджеті |
| Прибрати невикористані ключі локалей | ≤ 36 КБ (за грубою оцінкою 214 + 217 ключів не знайдено буквально) | велика частина — динамічно складені ключі (`pack.react.*`, `ui.wave.task.*`), без перевірки сторожем i18n можна зламати текст; потрібен окремий сторож «ключ без читача» з мутацією (закон 1) |
| Діалоги: `textKey` (32 КБ) виводити з `id` вузла за конвенцією `dlg.<id>.<node>` | ≈ 25–30 КБ | перегенерація 45 файлів і зміна валідатора; ризик розбіжності ключів |
| Діалоги й квести: `speaker`/`titleKey` лишаються, поле `id` у `nodes` дублює ключ мапи | ≈ 9 КБ | форма файлів змінюється, валідатор і мутації переписуються |

Висновок: чесного запасу без зміни архітектури — ≈ 62 КБ (зроблено); ще ≈ 37 КБ дають титри. Далі кожен варіант або
переносить байти в інше місце (PNG, окремий чанк), або чіпає форму контенту. Поріг 2,5 МБ при цьому залишається
за зростання коду ≈ 60–100 КБ на місяць близьким: наступне рішення — або свідоме підняття порога з поясненням `why`,
або ліниві чанки локалей.
