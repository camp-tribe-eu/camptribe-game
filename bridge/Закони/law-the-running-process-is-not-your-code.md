# Запущений процес — не той код, який ти щойно написав

Процес, кеш, каталог збірки й гілка живуть окремо від того, що я щойно
написав. Перш ніж звинувачувати код — перезапустити й звірити час.

**Що робити завжди:**
1. `ps lstart` проти `stat mtime` файлу конфігу. Процес, що стартував
   раніше за `.env`, ніколи не чув про новий ключ.
2. Не чіпати стан, яким володіє живий процес: `.next` під збіркою,
   скрипт під собою, базу під міграцією.
3. Комітити рано. Робоча копія і `/tmp` не переживають сесії; вціліє
   лише запушене.
4. Перевіряти гілку після КОЖНОГО відволікання.
5. Збережений id прогону застаріває — перераховувати від HEAD.
